# 運用メモ（確認のしかた・試し方）

日々の確認と、投稿せずに試す方法。全部ブラウザーだけでできます。
パソコンに何かを入れる必要はありません。

---

## 1. いちばん大事なこと

- 投稿の予定は `posts.json` に書いてあります。**予定時刻になるまで何も出ません。**
- GitHub Actions が **毎時23分** に様子を見にきて、予定時刻を過ぎた投稿があれば
  **1回に1件だけ** 公開します。
- 公開した記録は `state.json` に残ります。**同じ投稿が2回出ることはありません。**
- GitHub の定時実行は**時刻を保証していません。** 混んでいると遅れたり飛ばされたり
  します。12:00の予定が12:23や13:23になることはあります（出ないわけではありません）。

---

## 2. 毎日の確認（30秒）

1. リポジトリの **Actions** タブを開く。
2. 左の一覧から **「Threads 自動投稿」** を選ぶ。
3. 緑のチェックが並んでいれば正常です。

### 緑なのに「何も投稿されていない」とき

それが正常です。実行をクリックして `post` を開くと

```
公開する投稿はありません。
```

と出ているはずです。予定時刻がまだ来ていないという意味です。

### 見分け方

実行の名前の下に、どうやって動いたかが出ます。

| 表示 | 意味 |
| --- | --- |
| Manually run by haracannett | パソコンのタスクから呼ばれた、または手で押した |
| （何も書いていない／schedule） | GitHub の定時実行で動いた |

**毎日 12:05 ごろと 20:30 ごろに「Manually run by haracannett」が並んでいれば正常です。**
これがパソコンから呼び出しているぶんです（下の「パソコンから呼び出すしくみ」参照）。

> GitHub の定時実行（毎時23分）は、設定してから10日以上まったく動きませんでした。
> 2026-11-12 の夜から散発的に動きはじめましたが、毎時あるはずの実行の大半は
> 飛ばされたままで、当てにできません。原因は分かっていません。
> パソコンからの呼び出しと両方が動いても、二重に投稿されることはありません
> （`state.json` で公開済みを管理しているため）。

### 色の意味

| 色 | 意味 | どうするか |
| --- | --- | --- |
| 緑（成功） | 正常 | 何もしなくてよい |
| 黄（警告つき成功） | 中を見る | 下の「要確認」を読む |
| 赤（失敗） | 中を見る | 下の「要確認」を読む |

---

## 3. 投稿せずに試す（dry-run）

**Threads には何も出しません。** 出すはずだった内容を表示するだけです。

1. **Actions** タブ →左の一覧から **「Threads 自動投稿」** を選ぶ。
2. 右側の **「Run workflow」** ボタンを押す。
3. **「投稿せずに内容だけ表示する」にチェックが入っていることを確認する。**
   （最初からチェックが入っています）
4. 緑の **「Run workflow」** を押す。
5. 10秒ほどで実行が始まります。クリックして `post` を開くと内容が見えます。

出てくる文字の意味。

```
トークンOK: @can.nett として接続できました。
```
→ トークンが生きています。ここが失敗したらトークンを取り直します。

```
公開する投稿はありません。
```
→ 予定時刻を過ぎた投稿がまだありません。正常です。

```
投稿します: yuzu-lime-name-gap
左から「ライム」と「ゆず」です。
...
写真: https://raw.githubusercontent.com/...
アフィリエイトのリプライ: yuzu-lime-photo-gap
【PR】車で使えるペット用ドライブベッドを...
```
→ 次に出る予定の中身です。**この時点ではまだ出ていません。**

### 本当に投稿したいとき（手動）

同じ手順で、**3番のチェックを外して**から実行します。

> **注意：チェックを外すと本当に Threads に出ます。** 取り消せません。
> ただし、予定時刻を過ぎた投稿が無ければ何も出ません。

## 4.「要確認」が出たとき

公開を送ったあと、Threads から返事が来ないまま通信が切れることがあります。
このとき送り直すと**同じ投稿が2つ並ぶ**ので、ボットは送り直さずに止まります。

実行が赤くなり、ログにこう出ます。

```
要確認: yuzu-lime-name-gap（post）が出たかどうか分かりません。
```

### やること

**まず Threads を自分の目で見てください。** その投稿が出ているかどうかだけ確かめます。

多くの場合、**次の実行（次の23分）でボットが自分で解決します。** Threads に
問い合わせて、出ていれば記録して先へ進み、出ていなければやり直します。
**1〜2時間待って緑に戻れば、何もしなくて大丈夫です。**

何時間たっても赤いままのときは、`state.json` を見てください。

- 出ていた場合 → その投稿の `pending` を消して、`media_id` に投稿のIDを書く
- 出ていなかった場合 → その投稿の記録ごと消す（次の実行でやり直します）

分からなければ、この状態のまま相談してください。**勝手に二重投稿されることはありません。**

## 5. 投稿を増やす・直す

`posts.json` を編集します。GitHub の画面で鉛筆マークから直せます。

```json
{
  "id": "重複しない名前",
  "scheduled_at": "2026-12-01T12:00:00+09:00",
  "text": "本文（500文字まで）",
  "image": "photos/ファイル名.jpg",
  "affiliate": {
    "text": "ひとこと説明",
    "url": "https://..."
  }
}
```

- `scheduled_at` は **必ず `+09:00` を付ける**（日本時間という意味）。
- `image` は無くても構いません。写真を足すときは `threads_bot/photos/` に
  JPEGかPNG（8MBまで）を置きます。**位置情報が入った写真は自動ではじかれます。**
- `affiliate` があるときだけ、リプライでリンクを出します。
  広告表記（【PR】）は自動で付きます。
- 書き方を間違えると、実行が赤くなって理由を教えてくれます。
  **間違ったまま投稿されることはありません。**

## 6. トークンが切れたとき

長期トークンは **60日** で切れます。「Threads トークン更新」ワークフローが
1日と15日の3:37に延長します。

ただし **`GH_PAT` を登録していないと、新しいトークンが保存されません。**
いまは未登録なので、いずれ手で入れ直すことになります。
（警告は出ますが、ワークフローは失敗しません）

トークンが切れると、dry-run のときに
`トークンで接続できませんでした` と出ます。そうなったら取り直して、
**Settings → Secrets and variables → Actions → `THREADS_ACCESS_TOKEN`** を
書き換えます。

## 7. パソコンから呼び出すしくみ

GitHub の定時実行が動かないため、**自宅のパソコンから1日2回このワークフローを
呼び出しています。**

| | |
| --- | --- |
| タスクの名前 | `ThreadsBot-Post`（Windows のタスクスケジューラ） |
| 動く時刻 | 毎日 **12:05** と **20:30** |
| 中身 | `開発\threads-research\threads-bot-run.ps1` |
| ログ | `開発\threads-research\logs\threads-bot.log` |

パソコンが消えていた時刻のぶんは、**次に起動したときにまとめて実行されます。**
投稿は1回につき1件なので、2件たまっていれば次の回で2件目が出ます。

### 手で動かしたいとき

PowerShell を開いて、

```powershell
cd "$env:USERPROFILE\OneDrive\Desktop\開発\threads-research"
.\threads-bot-run.ps1 -DryRun     # 動作確認。Threadsには出さない
.\threads-bot-run.ps1             # 本番。条件が合えば実際に投稿する
```

### 止めたいとき・再開したいとき

```powershell
Disable-ScheduledTask -TaskName 'ThreadsBot-Post'
Enable-ScheduledTask  -TaskName 'ThreadsBot-Post'
```

### 時刻を変えたいとき

```powershell
Set-ScheduledTask -TaskName 'ThreadsBot-Post' -Trigger @(
  (New-ScheduledTaskTrigger -Daily -At 21:00),
  (New-ScheduledTaskTrigger -Daily -At 9:00)
)
```

## 8. 困ったときに見る場所

| 知りたいこと | 見る場所 |
| --- | --- |
| 今日動いたか | Actions タブ →「Threads 自動投稿」 |
| 何が出たか・出なかったか | その実行をクリック → `post` を開く |
| どの投稿が公開済みか | `threads_bot/state.json` |
| 次に何が出るか | `threads_bot/posts.json` の `scheduled_at` |
| しくみの説明 | `threads_bot/README.md` |
